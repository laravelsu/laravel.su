---
title: "Код говорит о намерении"
description: "Вызывающий код просит модель архивироваться и не управляет её атрибутами вручную."
---

После подключения `Archivable` контроллеры и команды не обязаны знать, как именно хранится архивное состояние:

```php
$post->archive();

$archivedPosts = Post::archived()
    ->latest('archived_at')
    ->get();
```

Сравните это с прямым изменением атрибута:

```php
// Контроллер сам воспроизводит правило модели.
if ($post->archived_at === null) {
    $post->archived_at = now();
    $post->save();
}

// Контроллер сообщает только требуемое действие.
$post->archive();
```

Второй вариант следует принципу [«Говори, а не спрашивай»](/library/getters-and-setters). Мы просим модель выполнить
действие, вместо того чтобы получить её данные, принять решение снаружи и затем по шагам изменить состояние.

Это различие особенно заметно со временем. Если вместо `archived_at` появится `status` со значением `archived`, изменится
только `Archivable`. Контроллеры, консольные команды и обработчики очередей продолжат вызывать `$post->archive()`.

Метод `isArchived()` не противоречит этому принципу. Вопрос уместен, когда от состояния действительно зависит следующий
шаг, например отображение кнопки:

```php
@if (! $post->isArchived())
    <button type="submit">Отправить в архив</button>
@endif
```

Проблема начинается не с чтения состояния, а с копирования правила изменения в вызывающий код. Проверить состояние для
интерфейса нормально; вручную выставлять `archived_at` в каждом контроллере — нет.
