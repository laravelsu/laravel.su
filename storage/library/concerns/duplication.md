---
title: "Когда одинаковый код становится проблемой"
description: "Дублирование опасно не числом строк, а несколькими версиями одного правила."
---

Представим обычную задачу: публикацию можно отправить в архив. Сначала метод появляется в `Post` и выглядит вполне
уместно:

```php
class Post extends Model
{
    public function archive(): void
    {
        $this->archived_at = now();
        $this->save();
    }
}
```

Затем архив понадобится комментариям и страницам. Проще всего скопировать метод:

```php
class Comment extends Model
{
    public function archive(): void
    {
        $this->archived_at = now();
        $this->save();
    }
}
```

Две копии ещё не пугают. Проблема проявится при первом изменении правила. Допустим, повторная архивация не должна менять
первоначальную дату. Метод в `Post` исправили, а про `Comment` забыли. Одинаковое действие теперь даёт разный результат в
зависимости от модели.

```php
public function archive(): void
{
    // Сохраняем время первой архивации, а не последнего вызова метода.
    if ($this->archived_at !== null) {
        return;
    }

    $this->archived_at = now();
    $this->save();
}
```

Таким образом, мы устраняем не просто повторяющиеся строки. Нам нужно **одно место, в котором определено правило
архивации**. Тогда исправление автоматически получают все модели, использующие это правило.

Наследование здесь не помогает. `Post` и `Comment` уже наследуются от Eloquent `Model`, а общий класс вроде
`ArchivableModel` вынудит строить иерархию вокруг одной необязательной возможности. Архивация нужна некоторым моделям,
но не обязана становиться свойством каждой модели приложения.

Именно для такого случая подходит Concern: общие методы записываются один раз, а модели подключают их по необходимости.
