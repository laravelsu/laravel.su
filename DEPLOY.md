# Запустить laravel.su

Для Compose требуется Docker. Для развёртывания требуется SSH-доступ root к `148.253.210.79`.

PHP сайта закреплён на 8.4.27 и копируется из официального образа `php:8.4.27-zts-bookworm` в FrankenPHP. ZTS и shared embed сохраняются.

Envoy использует PHP 8.4 для CLI и FPM и проверяет минимальную версию 8.4.27 до maintenance mode. Системные пакеты обновляются отдельно.

## Запустить через Compose

В чистом checkout выполните команды:

```sh
export APP_KEY="base64:$(openssl rand -base64 32)"
export APP_URL=http://localhost:8080
docker compose -f compose.yml up -d --build
curl --fail http://localhost:8080/up
```

Сохраните APP_KEY в локальном `.env` перед повторным запуском. Не коммитьте этот файл.
SQLite, загрузки и сессии находятся в отдельных именованных томах. Команда `docker compose down -v` удаляет эти данные.

## Развернуть через Kamal

Из чистого checkout нужного коммита выполните:

```sh
bin/deploy
```

Скрипт отправляет только файлы Git-коммита, собирает образ на сервере и запускает Kamal 2.12.0 в официальном контейнере. Локальные Ruby и Docker для этого не нужны. SSH и Kamal запрашивают пароль root, если вход по ключу ещё не настроен.

Каталог релизов расположен в `/opt/laravel-su/releases`. Постоянный APP_KEY и TLS-сертификат находятся в `/opt/laravel-su/shared`. Registry слушает только `127.0.0.1:5555`. SQLite хранится в томе `laravel-su-sqlite`, загрузки в `laravel-su-uploads`, сессии в `laravel-su-sessions`.

Сайт принимает запросы на этих адресах:

- `http://148.253.210.79`
- `https://148.253.210.79:88`
- `http://laravel.su`
- `https://laravel.su:88`

Первый запуск создаёт самоподписанный сертификат для IP и домена на 365 дней. Браузер показывает предупреждение о доверии. HTTP не перенаправляется на HTTPS. Порт 443 остаётся у существующего сервиса.

Проверьте маршрутизацию домена до изменения DNS:

```sh
curl --fail --resolve laravel.su:80:148.253.210.79 http://laravel.su/up
curl --insecure --fail --resolve laravel.su:88:148.253.210.79 https://laravel.su:88/up
```

Позднее направьте A-запись `laravel.su` на `148.253.210.79`. Удалите старую AAAA-запись, если IPv6 остаётся на другом сервере. DNS скрипт не меняет.

Для доверенного сертификата после смены DNS замените файлы `tls.crt` и `tls.key` в `/opt/laravel-su/shared` сертификатом домена и выполните `bin/deploy`. Цепочка сертификатов должна быть в `tls.crt`. Автоматическое продление в этот минимальный скрипт не входит.

Это новая SQLite-база. Скрипт выполняет миграции, но не переносит данные со старого сайта. GitHub OAuth, Telegram и почта требуют отдельных настроек.

## Проверить сохранность данных

Сделайте резервную копию SQLite через SQLite backup API перед обновлением схемы. Откат контейнера Kamal не откатывает миграции базы.

Существующие контейнеры не входят в конфигурацию этого приложения. Не используйте глобальные `docker system prune`, `docker stop` или `kamal remove` для обслуживания сайта.

## Переключить Telegram-антиспам

Настройте `/opt/laravel-su/shared/boyarin/.env` и выполните из чистого checkout:

```sh
bin/deploy-boyarin
```

Обработчик `https://148.253.210.79:88/webhook/telegram` работает в отдельном
контейнере без публичного порта. Скрипт сохраняет очередь Telegram и загружает
публичный сертификат. Для webhook по IP самоподписанный сертификат содержит
`CN=148.253.210.79`, а SAN включает IP как имя DNS и адрес IP.

После смены сертификата или URL повторите регистрацию webhook. При переходе
на доменный сертификат URL webhook также должен использовать этот домен.
Подробности находятся в `boyarin/README.md`.
