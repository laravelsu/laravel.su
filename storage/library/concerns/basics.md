---
title: "Трейт и Concern"
description: "Трейт — механизм PHP, а Concern — правило организации связанных методов."
---

[Трейт](https://www.php.net/manual/ru/language.oop5.traits.php) — конструкция языка PHP. Он позволяет добавить методы и
свойства в класс без наследования:

```php
trait Archivable
{
    public function archive(): void
    {
        // ...
    }
}

class Post extends Model
{
    use Archivable;
}
```

PHP понимает ключевые слова `trait` и `use`, но ничего не знает о Concerns. **Concern — принятое в Laravel название для
трейта, методы которого решают одну задачу модели.** `Archivable` отвечает за архив, `HasSlug` — за адрес записи,
`Publishable` — за публикацию.

Поэтому не каждый трейт стоит называть Concern. Трейт с методами `formatDate()`, `sendEmail()` и `clearCache()` лишь
прячет случайный набор функций в другом файле. У такого кода нет общей причины для изменения, а его название не может
честно объяснить содержимое.

Laravel использует тот же приём внутри Eloquent. Базовая модель собрана из
[`HasAttributes`, `HasEvents`, `HasRelationships` и других Concerns](https://github.com/laravel/framework/blob/13.x/src/Illuminate/Database/Eloquent/Model.php).
Каждый из них отвечает за отдельную часть работы модели. Поэтому код атрибутов, событий и связей не собран в одном
огромном файле `Model.php`.

После `use Archivable` его методы становятся методами самой модели:

```php
$post->archive();
$comment->archive();
```

Внутри трейта `$this` будет конкретным экземпляром `Post` или `Comment`. Concern поэтому может читать атрибуты модели,
сохранять её и добавлять условия к запросам. Вместе с этой свободой появляется важное требование: все подключающие его
модели должны понимать одинаковый смысл этих операций.

<div class="p-3 rounded bg-body text-balance border border-dashed">
    Хороший Concern можно описать одним коротким предложением: «эта модель умеет архивироваться». Если для объяснения
    приходится перечислять несколько несвязанных задач, методы лучше разделить.
</div>
